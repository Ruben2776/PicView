# Image, Interface and Background Settings Belong to a Main Window

Nine more **Settings** are **Window Settings**, as ADR-0038 defines them: Side-by-Side (`WindowSettings.IsSideBySide`), looping (`IsLooping`), **Zoom to Fit** (`IsZoomedToFit`), scrolling (`IsScrollingEnabled`), the three interface settings (`ShowInterface`, `ShowBottomBar`, `ShowHoverBar`), the image background choice (`BackgroundChoice`) and the constrained background (`IsConstrainingBackgroundColor`). Each is a bindable in the `WindowSettings` of its **Main Window**, read from the record by `WindowSettings.FromRecord` when the window is made at App Start, copied by `WindowSettings.CopyFor` for a window opened from another, and written back by `WindowSettings.Store` only when the window closes; changing one in a window changes nothing in another, nothing writes the record or saves on a change, and `GlobalSettingsViewModel` no longer has them. A tab follows each through `TabViewModel.FollowWindowSetting(pick, withoutWindow)`, the one way a tab follows a setting of the window it is in: it switches to the next window's value when `CurrentWindowSettings` publishes the tab's new window, gives the fallback for a tab with no window (the record's, for tests), and never subscribes to a closed window's settings, which it checks through `WindowSettings.IsDisposed` and catches as `ObjectDisposedException` for a window that closes between the check and the subscribe. A tab moved to a window whose value differs catches up once, through the same handler as a live change; one moved to a window that agrees does nothing, as `IsShowingPair` and the looping follower both drop a repeated value. `TabViewModel.IsShowingPair` is the window's Side-by-Side or the tab's comparing state (the comparison options stay per tab); `TabViewModel.PairSettings()` gives it with the window's looping, and `IterationHelper.GetIteration` takes looping as a parameter. Print, convert and the zoom previewer have no comparing state to show, so they read the window's raw Side-by-Side (`PrintJobStarter`, `ConversionHelper`, `ZoomPreviewer`). `MainWindowViewModel.Interface` combines the window's own three interface settings with its Window Mode through `InterfaceVisibility.For`, which is unchanged. `WindowFitter.Follow()` follows its own window's Zoom to Fit and scrolling and the shown tab's `IsShowingPair`, so another window's toggle fits nothing here, and keeps the Screen Margin from `GlobalSettingsViewModel.WindowMargin`, which stays an App Setting. The input path reads its own window's scrolling from the bindable's `CurrentValue`, `vm.WindowSettings.IsScrollingEnabled.CurrentValue` in `KeybindRouter` and in `ContextualActionHandler.ScrollsImage(bool, IZoomScrollTarget?)`, so a key press or a wheel step allocates nothing; `InputAllocationTests` guards it and runs only in Release. Each Main Window paints its own two brushes, `WindowSettings.ImageBackground` and `WindowSettings.ConstrainedImageBackground`, which its viewers bind through `ParentWindowContext`: `BackgroundManager.Follow(WindowSettings)`, attached in `MainWindowLifecycle.Create` before the window shows, paints them on the UI thread from the window's own choice and constrain setting when it is attached and on each change, and ends when the window disposes its settings. `BackgroundManager.ChangeBackground(WindowSettings)` moves the window's choice on to the next one (the B key and the `ChangeBackground` Action), and `ToggleHelper.ToggleConstrainBackgroundColor` toggles the window's constrain setting; both only write the window's bindable. The Settings window belongs to no Main Window, so its palette and its constrain checkbox bind through `MainWindows.ActiveWindow`, and `IThemeService.SetBackground` and `BackgroundManager.SetBackground(MainWindowOverviewViewModel?, int)` set the Active Main Window's choice and do nothing when none is open. The five menu texts that follow a setting and the language are derived per window, in `WindowSettings.LoopingText`, `ScrollingText`, `InterfaceText`, `BottomBarText` and `HoverBarText`, from the window's setting and `TranslationViewModel` bindables, two of which, `LoopingEnabled` and `LoopingDisabled`, were added for looping; `GlobalSettingsViewModel.FileHistoryText` is the one left there. `WindowSettingRecordReadsTests` has a third scan, which fails on any read or write of the nine record properties through their group (`ImageScaling`, `Zoom` or `UIProperties`) outside `WindowSettings`, `AppSettings` and `SettingsManager`.

Before this, each of the nine was one shared bindable on `GlobalSettingsViewModel` with a write-through to the record and a coalesced save, handed to every window and every tab, so a toggle in one Main Window reached all of them and was saved at once. The background was one choice and one pair of brushes for the process: `BackgroundManager.SetBackground()` ran at App Start before any window existed, one `BackgroundManager.Follow` lived for the process, and `ChangeBackgroundAsync` saved the settings. The input path read `Settings.Zoom.ScrollEnabled` from the record, and the fitter, print, convert and the zoom previewer read the shared bindable or the static record.

## Considered Options

- **Keep the write-through and add a per-window override.** The record would stay the value for every window that has no override, so a toggle would still reach a window that did not change it, and the record would hold the last change made in any window, which is the "last change wins" ADR-0038 rejected.
- **Leave the hover bar and the background app-wide.** The interface settings would be split across two owners, and `InterfaceVisibility` would take two of its three inputs from the window and one from the app. The background's brushes would still be made once, before any window exists, and the B key would change every window. The hover bar's only control is in the Settings window, but the Settings window already edits the Active Main Window, so the owner kept it per window.

## Consequences

- `GlobalSettingsViewModel` keeps five Action settings, `IsIncludingSubdirectories`, `IsFileHistoryEnabled`, `IsShowingFullPathInTitleBar`, `IsShowingTaskbarProgress` and `IsOpeningInSameWindow`, which `InitializeActionSettings` starts, and the extra ones, `ShowFadeButtons`, `WindowMargin` and `GalleryMouseWheelBehavior`, which `InitializeExtraSettings` starts.
- A crash loses the session's changes to these nine too, as ADR-0038 says of the others; App Settings still save at once.
- The guard cannot see an alias of a whole group (`var ui = Settings.UIProperties;`, then `ui.Looping`), because those groups also hold App Settings. A read through an alias is found in review. A new allowed file needs a reason in the test, as for the other scans.
- A Settings window control for one of the nine shows and edits the Active Main Window. Where no Action writes a setting its binding may be two-way, Stay Centered being the one; `SettingBindingContractTests` requires every other `IsChecked` binding to a `WindowSettings` member beside an Action to be `Mode=OneWay`, as for `GlobalSettings`.
- `WindowSettings` holds the two brushes as `object?`, as it lives in Core and cannot name an Avalonia brush; only `BackgroundManager` makes them. A copied window carries none from its opener, and derives its own when `BackgroundManager.Follow` is attached.
- The process-level background paths are gone: `BackgroundManager.SetBackground()`, `SetBackground(int)`, `SetBackground(GlobalSettingsViewModel, int)`, `ChangeBackgroundAsync` and `Follow(GlobalSettingsViewModel)`. `ThemeManager.DetermineTheme` runs before the first Main Window is made, so the brushes it paints resolve in the right theme.
- The "toggle scrolling" items in the bottom bar and title bar menus had no command, so choosing one did nothing; they now run the `ToggleScroll` Action, and `SettingBindingContractTests` fails on a menu item that shows a published setting and runs no Action.
- The macOS "Toggle UI" item still has no checked state bound; that is unchanged.
- A closed window's `WindowSettings` takes no background change: `BackgroundManager.ChangeBackground` and `SetBackground` do nothing for it, and a brush posted just before the window closed is not made.
- ADR-0034's rule that a follower reading the record calls `InitializeActionSettings()` first holds for the five settings that remain, and is void for these nine, which a follower reads from the window.
- The settings file keeps its shape and its version; no migration.
- The gallery's look, the dock edge and the start-docked choice, the last of the Window Settings design, are slice 4 and still App Settings.
- Supersedes ADR-0020's list of fourteen, which became thirteen under ADR-0038, as a list of what `GlobalSettingsViewModel` publishes, ADR-0021's "every Main Window derives from the same three", ADR-0024's and ADR-0032's "side-by-side is still global" and the static reads they leave to conversion, printing and the fitter, ADR-0026's source of the fitter's zoom to fit, scrolling and side by side, ADR-0034's thirteen in `InitializeActionSettings`, and ADR-0036's six menu texts on `GlobalSettingsViewModel`.
